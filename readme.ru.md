# TGTunnel

**TGTunnel** — экспериментальный Android-проект локального MTProto-прокси для Telegram. Это небольшой пет-проект, который развивается в свободное время. Проект предоставляется как есть: работа всех сетевых сценариев пока не гарантируется.

- **Платформа приложения:** Android.
- **Исходный код:** [GitHub](https://github.com/DevAyuGlass/TgTunnel).
- **Распространение:** APK из GitHub Actions / GitHub Releases.

## Возможности

- Локальный TCP listener на `127.0.0.1`.
- Генерация и локальное сохранение 16-байтового MTProto secret.
- Формирование ссылки `tg://proxy` для добавления локального прокси в Telegram.
- Обработка obfuscated MTProto handshake и AES-CTR.
- Попытка подключения к Telegram через TLS WebSocket (`kws{dc}.web.telegram.org/apiws`).
- Резервная попытка прямого TCP-подключения к Telegram DC на порту 443.
- Журнал событий и копирование логов для диагностики.

**Важно:** создание локального listener ещё не означает, что туннель подключился к Telegram. Для работы нужны успешное исходящее соединение с Telegram и активный процесс TGTunnel на том же устройстве, где запущен Telegram.

## Установка

1. Откройте раздел **Actions** репозитория или страницу **Releases**.
2. Скачайте APK нужной сборки.
3. Установите APK на Android. При установке сборки вне Google Play Android или Play Protect могут показать предупреждение о неизвестном приложении.
4. Запустите TGTunnel и нажмите **Подключиться**.
5. Откройте созданную приложением ссылку в Telegram и подтвердите добавление прокси.

Ссылка использует адрес `127.0.0.1`, поэтому она предназначена для Telegram на **том же устройстве**. Она не создаёт публичный прокси-сервер и не подходит для подключения с другого телефона или компьютера.

## Настройки

- **Порт** — локальный порт listener. Если он уже занят другим приложением или плагином Telegram, выберите свободный порт.
- **Автозапуск** — запускать локальный listener при открытии приложения.
- **Подробные логи** — настройка для расширенной диагностики (если соответствующая детализация реализована в текущей версии).

## Диагностика

### `EADDRINUSE`

Порт уже используется другим процессом. Проверьте, не запущен ли другой локальный прокси (например, плагин для Telegram), либо задайте другой порт в настройках TGTunnel.

### `ECONNABORTED` при подключении к `kws*.web.telegram.org:443`

Операционная система прервала исходящее TCP-соединение. Возможные причины — ограничения сети, VPN/фильтрация трафика или проблемы маршрутизации. Само по себе это сообщение не доказывает неисправность MTProto-handshake. Проверьте доступность Telegram из той же сети и посмотрите последующие строки журнала: в частности, результат попытки TCP fallback.

### `DC upstream connection failed`

TGTunnel не смог установить ни одно из предусмотренных исходящих подключений к выбранному Telegram DC. Скопируйте полный журнал событий и приложите его к сообщению об ошибке.

## Архитектура

- Android UI: Kotlin + Jetpack Compose.
- Android listener и транспорт: Kotlin, Android TLS и криптографические провайдеры.
- Отдельное ядро: C++17, CMake, Android NDK и Mbed TLS.
- JNI bridge присутствует в проекте; текущий Android listener/transport пока реализован на Kotlin и не использует C++ transport lifecycle.

Поддерживаемые Android ABI:
- `arm64-v8a`
- `armeabi-v7a`
- `x86_64`

Минимальная версия Android: API 24 (Android 7.0).

## Сборка Android APK

Из корня репозитория:

```sh
gradle --no-daemon -p android :app:assembleDebug :app:assembleRelease
```

Для локальной release-подписи задайте переменные окружения, используемые Gradle-конфигурацией проекта:

- `RELEASE_STORE_FILE`
- `RELEASE_STORE_PASSWORD`
- `RELEASE_KEY_ALIAS`
- `RELEASE_KEY_PASSWORD`

**Не публикуйте keystore, пароли или приватные ключи в репозитории.** Для GitHub Actions используются секреты репозитория.

## Сборка и тесты C++-ядра на Linux

Linux используется как среда разработки и не является поддерживаемой платформой приложения:

```sh
cmake -S . -B build -DTGTUNNEL_BUILD_TESTS=ON -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel
ctest --test-dir build --output-on-failure
```

## Ограничения текущей версии

- Проект экспериментальный; успешная сборка APK не подтверждает работоспособность подключения в каждой сети.
- Пока нет фонового foreground service: Android может завершить процесс приложения, если оно долго находится в фоне.
- Не реализованы Cloudflare Worker/H2 fallback, Fake-TLS domain mode и test-DC routing из upstream-проекта.
- Прямой TCP на порт 443 используется как резервный вариант после неудачи WebSocket.
- Linux-клиента нет; Linux нужен только для разработки и тестирования C++-ядра.

## Сообщить об ошибке

Перед созданием issue приложите:
- модель устройства и версию Android;
- тип сети (Wi-Fi или мобильная);
- используемый VPN, если он включён;
- полный журнал TGTunnel без MTProto secret и других личных данных.

Не публикуйте свой MTProto secret: он является частью конфигурации прокси.
